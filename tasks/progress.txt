## Codebase Patterns
- Database initialization is in a single `db.transaction()` block at startup in `queue/index.mjs`
- Use `INSERT OR IGNORE` for default data to ensure idempotency on restart
- Use `CREATE TABLE IF NOT EXISTS` for all table creation
- The `inspections` object at the top of `index.mjs` defines all inspection types with Korean names
- Per-inspection queue tables are created dynamically by looping over `Object.entries(inspections)`
- Server runs on port 9300, test with `timeout 5 node index.mjs` (exit code 124 = success)
- Working directory when running commands is `queue/` not the repo root
- The `current` table `inspection` field is a comma-separated list when a team has multiple simultaneous registrations
- Report inspection is exempt from duplicate constraints: it can coexist with any other inspection
- When removing a type from `current.inspection`, always use `split(",").filter().join(",")` pattern to handle N types (not just 2)
- SSE `init` event data includes `allBooths` object keyed by inspection type; `broadcastEvent("booth", { type, booths })` for real-time booth updates
- Frontend `useSSE.js` exports: `activeInspections`, `lastQueueUpdate`, `allBooths`, `lastBoothUpdate`, `connected`
- `getBoothsForType(type)` helper in index.mjs returns booth array for an inspection type - use for all booth queries and SSE broadcasts
- Booth enter/exit endpoints broadcast BOTH 'booth' and 'queue' SSE events; SMS notification sent after response for enter
- booth_log tracks active occupancy with `exited_at IS NULL`; exit updates this row
- When resetting/clearing data for an inspection type, remember to also reset booth state and broadcast both 'queue' and 'booth' SSE events
- For dynamic SQL filters (optional query params), build arrays of conditions/params and join with AND: `conditions.join(" AND ")`

## 2026-02-23 - US-006
- What was implemented: Added booth enter and exit API endpoints for assigning teams to booths and releasing them
- Files changed: queue/index.mjs
- **Learnings for future iterations:**
  - Enter endpoint (`POST /api/admin/booths/:type/:boothNum/enter`) does everything in a single transaction: validates queue entry and booth state, removes from queue, decrements inspection length, occupies booth, logs to booth_log and queue_log, cleans up current table
  - Exit endpoint (`POST /api/admin/booths/:type/:boothNum/exit`) clears booth, updates booth_log with exited_at, and inserts inspection_history for re-inspection tracking
  - SMS notification reuses the same pattern as the old enter endpoint: fetch sms_rank-th person BEFORE the transaction, call `sendSmsNotification()` AFTER response
  - Both endpoints broadcast both 'booth' and 'queue' SSE events since both booth state and queue state change
  - booth_log uses `exited_at IS NULL` to match the active log entry when updating exit time
  - The old `POST /api/admin/enter/:type` endpoint remains for backward compatibility (will be deprecated in US-008)
