## 0. 개요

전산시스템은 크게 다음 서비스들로 이루어져 있습니다.

* 검차 대기열
* 등록 대기열
* 인스펙션 시트
* 서류 제출
* 계측 시스템
* 성적 관리
* 코스 관리
* 엔트리 관리
* 대회 일정
* 계정 관리

사람 계정은 학생(`student`), 오피셜(`official`), 관리자(`admin`) 세 종류입니다. 오피셜은 계정마다 필요한 서비스 접근 수준을 한 목록에서 부여받고, 관리자는 모든 서비스 권한을 가집니다. 권한은 서열이 아니라 서비스별 허용 목록으로 판정됩니다.

홈과 사이드바의 Resources 섹션은 접거나 펼칠 수 있으며, 동일한 상태가 브라우저 `localStorage`에 저장되어 다음 방문에도 유지됩니다.

## 1. 검차 대기열

### 우선순위

검차 대기열은 우선순위 큐로서, 다음 규칙을 순서대로 따릅니다.

1. 초검 팀은 재검 팀보다 우선 처리
2. 사전 제출 서류에 따른 우선순위에 따라 처리
3. 선착순

* 각 하위 규칙은 상위 규칙이 동일한 그룹 내에서만 적용됩니다.
    * ex) 재검인 팀은 서류 제출에 따른 우선순위가 높더라도 초검 팀에 새치기당함
* 규칙 1과 2는 현장 상황에 따라 적용 여부가 조정될 수 있습니다.
    * 이 경우, 각 규칙의 적용 여부는 검차마다 다를 수 있습니다.
        * ex) 축전지 검차는 규칙 1, 2, 3 적용, 전기 검차는 규칙 1, 3 적용

### 동시 등록 제한

기본적으로, 한 팀은 한 번에 하나의 검차에만 대기할 수 있습니다.

단, 축전지 검차와 섀시 검차는 물리 검차 중 유일하게 동시에 대기할 수 있는 조합이며, 보고서(report)는 어떤 검차와도 항상 동시에 대기할 수 있습니다.

### 취소 페널티

다음 상황에 해당하는 경우, 해당 검차에 재등록 불가 페널티 10분이 부여됩니다.

* 검차 순번이 되었는데 검차장 앞에서 대기하고 있지 않은 경우
* 검차 순번이 되었는데 즉시 입차할 수 없는 경우
* 대기를 취소하는 경우

취소 페널티에는 다음과 같은 규칙이 적용됩니다.

* 팀은 스스로 대기를 취소할 수 없으며, 오피셜에게 취소를 요청해야 합니다.
* 페널티 시간은 현장 상황에 따라 조정될 수 있습니다.
* 취소 페널티는 검차마다 독립적으로 적용됩니다.
    * ex) 축전지 검차 취소 페널티는 전기 검차 등록을 막지 않음
* 초검인 팀이 대기를 취소한 경우, 다음번 등록 시에도 초검으로 처리됩니다.
* 오피셜은 검차 대기 관리 화면의 페널티 목록에서 `페널티만 해제`하거나, `해제 후 순번 복구`를 선택해 취소 전 접수 순번까지 복구할 수 있습니다.
    * 기능 배포 전에 부여된 페널티처럼 취소 당시 접수 정보가 없는 경우에는 순번 복구가 불가능합니다.

검차에 입차한 시점부터, 해당 검차가 진행중이더라도 다른 검차에 대기할 수 있습니다.

* 단, 첫 번째 검차가 끝나지 않았는데 두 번째 검차에 입차할 순서가 된 경우, 두 번째 검차에는 취소 페널티가 부여됩니다.

### 문자 알림

검차 대기 3번이 되었을 때, 검차 대기 시 입력한 전화번호로 안내 문자가 발송됩니다.

* 문자가 발송되는 대기 순번은 현장 상황에 따라 조정될 수 있습니다.
* 안내 문자에는 답장해도 처리되지 않습니다.
* 전화번호 오입력에 주의합니다.

### 기억할 점 & 생각할 점

#### 1. 권한

`queue.operate`는 대기열·부스·페널티·통계 운영 권한입니다. 우선순위, 취소 페널티 시간, SMS 알림, 검차 활성화 같은 설정은 `queue.manage`가 필요합니다. `queue.manage`에는 `queue.operate`가 포함됩니다.

#### 2. 대기대기줄

학생들이 새벽부터 어딘가에서 줄을 만들어서 대기 등록을 하려고 기다릴 텐데, 이러한 현상을 어떻게 처리할지 고민이 필요합니다.

개별 검차의 활성화 여부를 조정할 수 있으니, 검차 등록 태블릿은 미리 설치해 놓고 시간에 맞춰서 검차를 활성화할 수는 있습니다.

#### 3. Round-Robin Scheduling

이제 각 검차 슬롯마다 몇 분째 검차가 진행중인지 실시간 추적이 가능하고, 각 팀별 검차 통계도 확인이 가능합니다.

1시간 검차 시간제한을 두고 시간을 초과한 경우 일단 돌려보내고 다음 팀을 받으면, 초검인 팀이 한 번도 검차를 받지 못하고 오래 기다려야 하는 현상을 해소할 수 있습니다.

대신, 처음으로 검차를 완전히 통과하는 팀이 나오기까지의 시간이 더 오래 걸리게 됩니다. 또한, 부스에서 팀이 교체되는 횟수가 늘어나므로, 이전 팀을 빼고 다음 팀을 받는데 소요되는 시간이 증가합니다.

결과적으로 모든 팀이 검차를 완료할 때까지의 시간 총합은 증가합니다.

#### 4. 쉬려면

정확한 검차 통계를 얻으려면 각 부스 담당자 분들께서 잊지 말고 입차/출차 처리를 정확히 해주셔야 합니다.

또, 이제 학생들도 검차 부스가 몇 개고, 몇 분째 검차중인지 실시간 확인이 가능합니다. 부스가 입차 가능 상태로 10분 넘게 유지되면 학생들이 문의할 가능성이 큽니다. 잠깐 쉬실 때 부스를 비활성 상태로 전환하는 걸 잊지 말아주세요.

## 2. 등록 대기열

등록 데스크에서 선착순 대기를 접수하고, 참가자가 자신의 순번을 확인하며, 스태프가 등록 완료를 처리하는 기능입니다.

### 참가자 조회

1. 사이드바에서 `등록 대기열`을 엽니다.
2. 등록 시 입력한 엔트리 번호와 전화번호를 입력합니다.
3. `조회`를 누르면 현재 순번을 확인할 수 있습니다.

공개 화면에는 전체 대기 팀 수만 표시됩니다. 개인 대기 내역은 엔트리 번호와 등록 전화번호가 모두 일치할 때만 표시되며, 전화번호 자체는 응답에 포함되지 않습니다.

### 현장 접수 (`registration.manage` 또는 접수 전용 태블릿)

1. `등록 대기 관리`에서 `등록 대기 접수`를 엽니다.
2. 엔트리 번호를 입력하고 표시된 학교와 팀을 확인합니다.
3. 참가자 전화번호를 입력하고 개인정보 수집·이용 동의를 확인합니다.
4. `대기 등록`을 누르고 화면에 표시된 순번을 참가자에게 안내합니다.

접수가 닫혀 있거나, 비활성 팀이거나, 같은 팀이 이미 대기 중이면 등록할 수 없습니다. 공용 태블릿에는 사람 계정으로 로그인하지 않고, 관리자가 발급한 `등록 대기 접수` 전용 장비 코드를 한 번 입력해 페어링합니다.

### 대기 운영 (`registration.operate`)

`등록 대기 관리` 화면에서 팀의 등록 처리가 끝나면 `완료`를 누릅니다. 참가하지 않거나 잘못 접수된 팀은 확인 후 `취소`를 누릅니다.

동시에 두 운영자가 같은 항목을 처리하면 먼저 저장된 요청만 성공합니다. 화면은 SSE로 자동 갱신됩니다. 완료와 취소 후에도 제출 전화번호와 처리 시각은 감사 이력으로 보존됩니다.

### 접수 및 문자 설정 (`registration.manage`)

* `현장 대기 접수`: 신규 대기 등록을 열거나 닫습니다.
* `문자 안내`: 사전 순번 안내 문자를 켜거나 끕니다. Email/SMS 서비스에 SENS 설정이 있어야 켤 수 있습니다.
* `사전 안내 순번`: 검차 대기열과 같이 설정한 1~10번째 순번이 된 팀에 한 번 안내합니다.

팀 번호가 변경되어도 내부 팀 ID와 대기 이력은 유지됩니다. 팀을 비활성화하면 진행 중인 대기만 취소되고 완료·취소 이력은 삭제되지 않습니다. 이때 줄어든 대기열에 대해서는 사전 안내 문자를 보내지 않습니다 — 문자를 쓰는 대회 진행 중에는 팀 비활성화를 하지 않기 때문입니다. 사전 안내는 `완료`·`취소`로 대기열이 움직일 때만 발송됩니다. 과거 연도는 조회만 가능하고 모든 변경은 현재 한국 연도에만 허용됩니다.

## 3. 인스펙션 시트

### 사용 방법

1. 개인 휴대폰으로 인스펙션 시트에 들어갑니다.
2. 검차할 팀을 클릭하고, 자신이 담당한 검차 탭을 선택합니다.
3. 검차를 진행합니다.
    * PASS/FAIL 문항에서 해당하지 않는 항목은 `N/A`를 선택합니다. N/A도 입력 완료로 계산됩니다.
    * `메모 추가`를 누르면 해당 문항 아래에 여러 줄 메모를 작성할 수 있습니다. 입력 중 자동 저장되며 다른 곳을 누르면 대기 중인 내용이 즉시 저장됩니다.
    * 문항 옆 `?`를 누르면 새 탭에서 해당 연도의 대응 규정 조항을 엽니다. 규정이 여러 개면 먼저 조항을 선택합니다. 주황색 `?`는 규정 연결 검토 중이라 열리지 않으며, 직접 대응 규정이 없는 문항에는 버튼이 표시되지 않습니다.
4. 검차를 마치면 상단의 `PASS`, `FAIL` 버튼을 눌러 최종 상태를 지정합니다. `PASS`는 모든 응답 문항을 입력해 진행률이 100%가 된 뒤에만 선택할 수 있고, `FAIL`은 미입력 문항이 있어도 선택할 수 있습니다.

#### 리빙 포인트

* 상단의 문항 상태 맵은 현재 검차 탭의 문항을 순서대로 보여줍니다. PASS, FAIL, N/A, 기타 입력, 미입력을 색으로 구분하며 각 문항을 누르면 해당 위치로 이동합니다. 응답 문항이 없는 상태 추적용 카테고리는 별도 입력 없이 PASS/FAIL을 선택할 수 있습니다.
* FAIL 항목과 미입력 항목이 있으면 카테고리의 최종 PASS/FAIL 판정 여부와 관계없이 상태 맵 아래에 각각 목록이 표시됩니다. 목록의 문항을 누르면 해당 위치로 이동합니다.
* `소분류 목차`를 열면 소분류와 그룹 이름을 한 번에 확인하고 이동할 수 있습니다.
* 체크테이블은 표 전체를 한 문항으로 계산하며, 현재 표에 존재하는 셀 하나만 체크해도 입력 완료로 처리합니다.
* 현재 카테고리에 작성된 메모가 있으면 시트 상단의 `메모 N개` 목록에서 한 번에 확인하고 해당 문항으로 이동할 수 있습니다. 카테고리를 바꾸면 해당 카테고리의 메모만 표시됩니다.
* 응답이나 메모를 실제로 변경하면 로그인 계정의 실명이 해당 카테고리 검차관 목록에 자동으로 추가됩니다. 수기로 입력하거나 삭제할 필요가 없습니다.
* 각 응답과 메모 아래에는 마지막으로 수정한 계정의 실명과 수정 일시가 각각 표시됩니다.
* 저장에 실패한 응답이나 메모는 해당 문항에 표시됩니다. 입력 내용은 유지되며 `재시도`를 눌러 다시 저장할 수 있습니다.
* 같은 문항을 다른 사용자가 먼저 저장했다면 뒤늦은 저장은 적용되지 않습니다. 화면은 로컬 입력을 버리고 서버 값을 표시하며 새로고침 후 다시 작성하라고 안내합니다.

### 기억할 점 & 생각할 점

#### 1. 권한

검차표 입력과 판정에는 `inspection.operate`, 검차 템플릿 생성·변경·삭제·가져오기에는 `inspection.manage`가 필요합니다. 인스펙션 권한은 검차 대기열의 `queue.operate`/`queue.manage`와 서로 독립적입니다. 규정 연결 변경도 `inspection.manage`가 필요합니다.

템플릿 관리의 규정 연결 버튼에서 차량기술규정/경기진행규정을 검색해 하나 이상 연결하거나, `직접 대응 규정 없음`으로 표시할 수 있습니다. JSON 내보내기에는 문항의 안정 키와 규정 연결이 함께 포함됩니다. `규정 연결 가져오기`는 이 동일한 JSON에서 연결만 갱신하며 템플릿이나 기존 답변은 삭제하지 않습니다. 일반 `JSON 가져오기`는 템플릿 전체를 교체하므로 용도가 다릅니다.

새 연도 템플릿을 복사하면 문항 안정 키와 규정 영구 키가 같은 연결만 검사합니다. 조항 번호만 바뀌고 내용 해시가 같으면 자동으로 새 번호를 따라가며, 내용이 바뀌거나 키가 사라지거나 새 연도 규정집이 아직 없으면 `검토 필요`가 됩니다. 이후 `동기화` 또는 `재검증`을 실행해도 내용이 바뀐 규정은 사람이 확인하기 전 자동으로 검증 상태가 되지 않습니다.

#### 2. 상태 추적

PASS/FAIL 상태는 성적 관리에 연동됩니다. 입력하는 것을 잊지 말아주세요.

틸팅, 소음, 우천, 제동 검차는 PASS/FAIL 상태 추적에만 사용되므로, 시트 자체는 비어 있습니다.

#### 3. 공지용 PDF

검차 템플릿에 따라서 자동 생성되는 공지용 인스펙션 시트 PDF가 있습니다, 만 아무래도 직접 엑셀로 알록달록하게 만든 것보다는 퀄리티가 좀 떨어집니다. 확인해보고 결정이 필요합니다.

구현상의 문제로 섀시(공통) 인스펙션 폼에서 1, 2, 3차 항목을 모두 제거했습니다. 꼭 필요했던 내용인지 확인이 필요합니다.

## 4. 서류 제출

### 권한

서류 제출 기능은 `student` 계정에 표시됩니다. 제출 현황·파일 검토는 `documents.operate`, 세션·학생 매핑과 파일 변경·삭제는 `documents.manage`가 필요합니다.

student 권한 등록을 위한 계정 생성은 admin 권한 사용자만 가능합니다.

### 사전 준비

학생들은 각 팀별로 한 명씩 student 계정을 등록해야 합니다.

서류 제출이 시작되기 전에 계정 등록이 완료되어야 하니, 미리 팀들에게 제출에 사용할 "구글 로그인이 가능한 이메일 주소" 를 조사해 계정을 생성해 두어야 합니다.

계정을 생성한 후, 서류 제출 관리 메뉴에서 각 팀의 student 계정을 지정합니다.

### 사용 방법

1. 서류 제출 관리 메뉴에서 `세션 생성` 버튼을 클릭합니다.
2. 세션 이름과 학생들에게 표시할 공지 메시지를 입력합니다.
3. 제출 시작일과 마감일, 시간을 입력합니다.
5. 지각 마감일과 시간을 입력합니다.
    * 지각 제출을 허용하지 않으려면 비워둡니다.
6. 제출 파일의 총합 용량 제한을 설정합니다.
7. 제출에 허용할 파일 확장자를 설정합니다.
    * 모든 파일 형식을 허용하려면 비워둡니다.
    * 파일 확장자는 , 로 구분되는 목록입니다. (예시: pdf, xlsx, zip)
8. 제출 대상 팀을 선택합니다.
9. 생성 버튼을 클릭합니다.

제출 세션 정보를 수정하려면, 서류 제출 관리 메뉴의 표에서 세션 이름을 선택하고 수정 버튼을 클릭합니다.

### 학생 사용 방법

1. 각 팀별로 조사했던 "구글 로그인이 가능한 이메일 주소" 로 로그인합니다.
2. Services 메뉴에 새로 표시되는 서류 제출 메뉴를 선택합니다.
3. 표시되는 제출 세션 중 하나를 선택합니다.
4. 파일을 업로드하고 제출합니다.

* 제출 완료 후 다시 파일을 제출하면 기존 제출은 새 제출로 교체됩니다.
* 정시 제출 완료 후, 지각 마감 기간에 새로 제출하면 지각 제출로 처리됩니다.

### 기억할 점

제출 마감 및 지각 여부는 업로드 완료 시간을 기준으로 판정합니다.
한 제출에 업로드할 수 있는 파일 개수는 최대 100개입니다.

## 5. 계측 시스템

일반 기록과 경기 운영에는 `traffic.operate`, 계측 설정·센서 매핑·전체 기록 또는 로그 삭제에는 `traffic.manage`가 필요합니다.

### 기록 열람

계측 시 입력한 이벤트 이름으로 기록을 열람합니다.

각 기록의 콘터치와 코스 이탈 개수를 입력하면 성적 관리 시스템에 자동으로 반영됩니다.

모든 계측 화면과 기록 표에서 `정상`, `DNS`, `DNF`, `DSQ` 중 하나로 판정합니다. 측정시간이 있는 기록을 판정해도 원시 시간은 보존되며, `정상`으로 되돌리면 다시 성적 계산에 사용됩니다. 측정시간 없이 잘못 만든 판정은 `판정 취소`로 삭제합니다.

전광판 표시 여부는 판정과 별도로 전광판 버튼에서 변경합니다. DNS/DNF/DSQ도 표시를 켜면 전광판에 상태 문구로 나타납니다.

기록을 수동으로 추가하려면 기록 추가 버튼을 클릭합니다.

### 경기 모드

Chrome 브라우저로 계측 시스템 메뉴에 접속한 후, 계측기 컨트롤러를 컴퓨터와 연결합니다.

모든 경기 모드는 계측기 기록 조건을 만족하면 자동으로 기록을 저장합니다.

#### 가속

계측기의 센서 1을 출발 지점에, 센서 2는 도착 지점에 배치합니다.

출발 지점과 도착 지점 사이의 소요 시간을 기록합니다.

#### 스키드패드

계측기의 센서 1을 측정 지점에 배치합니다.

랩 2와 랩 4 기록을 합산하여 기록합니다.

#### 오토크로스

계측기의 센서 1을 출발 지점에, 센서 2는 도착 지점에 배치합니다.

출발 지점과 도착 지점 사이의 소요 시간을 기록합니다.

#### 내구

계측기의 센서 1을 출발선에 배치합니다. 첫 통과는 측정을 시작하고, 이후 통과마다 한 랩으로 기록합니다.

첫 랩이 완성되면 기록 한 건을 즉시 저장하고 이후 랩을 같은 기록에 누적합니다. `저장된 기록 후처리` 영역에서 정상/DNS/DNF/DSQ 판정, 전광판 표시, 콘터치와 코스 이탈을 수정할 수 있습니다. 이 Traffic 내구 판정은 Score의 공식 내구 입력 판정과 자동 동기화되지 않습니다.

`초기화`는 저장된 기록을 삭제하지 않고 현재 측정과 후처리 대상을 화면에서 닫습니다. 무선 물리 신호등에서는 마스터의 실제 OFF 확인 후 초기화가 완료되며, 확인 전에는 후처리 입력과 녹색등(새 측정 시작)이 잠기고 `OFF 확인 대기 · 다시 전송`이 표시됩니다.

#### 매뉴얼 모드

계측기 컨트롤러 없이 각 경기 모드의 측정 흐름을 시뮬레이션합니다. 컨트롤러 카드의 `매뉴얼 모드` 버튼을 클릭하면 활성화됩니다.

매뉴얼 모드에서는 녹색등을 점등한 후 화면에 표시되는 센서 버튼을 직접 클릭하여 센서 통과를 시뮬레이션합니다. 버튼 클릭 간의 실제 경과 시간이 기록됩니다. 기록 저장 등 이후의 모든 동작은 실제 컨트롤러 사용 시와 동일합니다.

매뉴얼 모드와 시리얼 컨트롤러 연결은 동시에 사용할 수 없습니다.

## 6. 성적 관리

집계·수동 점수·내구 입력에는 `score.operate`, 페널티·점수 설정과 성적 공개 전환에는 `score.manage`가 필요합니다.

### 사용 방법

* `기록` 을 선택하면 각 이벤트의 페널티가 반영된 시간 기록이, `성적` 을 선택하면 공식에 따라 계산된 점수가 표시됩니다.
* 각 팀 행을 클릭하면 해당 팀의 동적 이벤트별 세부 기록이 표시됩니다.
* XLSX 성적표에는 `가속`, `스키드패드`, `오토크로스`, `내구`, `스타팅오더`, `전체 점수표` 시트가 함께 포함됩니다. 각 시트는 별도 표제나 생성 정보 없이 공지용 표 데이터와 서식만 포함합니다.
* 보고서, 가점, 감점 항목은 각 셀을 클릭하여 수동 입력합니다.
* 에너지는 내구 입력 화면의 계측값과 판정에 따라 자동 계산되며 성적표에서는 읽기 전용으로 표시됩니다.

#### 페널티 설정

* 콘터치: 콘 1개당 추가되는 시간
* 코스이탈: 코스이탈 1회당 추가되는 시간
    * 코스이탈이 DNF인 이벤트는 정지콘 위반을 코스 이탈로 처리합니다.
* 출발지연: 출발지연 1회당 추가되는 시간 (내구 전용)

#### 점수 설정

경기진행규정의 점수 계산 공식의 각 요소입니다.

* 총점: 해당 이벤트의 최대 배점
* 완주점수: 컷오프 이내 완주 시 최소 보장 점수
* 컷오프: 최고 기록 대비 이 비율을 초과하면 완주점수만 부여
* 보고서와 에너지는 `총점`만 사용합니다. 보고서 입력 상한과 에너지 공식의 만점은 이 값으로 결정됩니다.

#### 내구 기록 입력

내구 경기 기록은 페이지 상단의 내구 입력 버튼을 클릭하여 수동 입력합니다.

* 각 셀을 클릭하여 기록을 입력하고, `Enter` 또는 입력창 옆의 **확인** 버튼을 눌러 저장합니다. 저장하지 않고 다른 곳을 클릭하거나 셀을 이동하면 입력값은 취소됩니다.
* 드라이버 1과 드라이버 2의 이름을 각 팀 행에 입력할 수 있습니다. 이름도 `Enter` 또는 **확인** 버튼으로 저장되며 내구 입력 화면의 XLSX 기록에 포함됩니다.
* `Enter`로 저장하면 해당 셀의 편집이 완료되며, 이어서 화살표 키를 누르면 마지막 입력 셀을 기준으로 해당 방향의 다음 셀 편집으로 이동합니다. **확인** 버튼은 Tab 순서에서 제외되므로 Tab은 다음 입력 셀로 바로 이동합니다. 이동 전에 저장하지 않은 입력값은 취소됩니다.
* 시간 입력 형식: M:SS.mmm 또는 SS.mmm
* 상단에서 내구 거리와 휘발유 계산 기준(L/2.31 또는 kg/2.95)을 설정합니다. 내구 거리도 `Enter` 또는 입력창 옆의 확인 버튼으로 저장합니다.
* 성적표와 같은 차량 유형 체크박스로 표시 팀을 필터링할 수 있습니다.
* 표 마지막 열의 **내구 진출** 스위치로 진출 여부를 지정하고, 상단의 **내구 진출팀** 필터로 진출 팀만 볼 수 있습니다.
* C/E 구분은 엔트리에 등록된 차량 유형(`C-Formula` 또는 `E-Formula`)에서 자동으로 적용됩니다. C-Formula는 연료 소비량과 추가 주유량을, E-Formula는 에너지미터의 순사용 전력량(사용 전력-회생 충전량)을 입력합니다.
* 보정 CO₂/100km는 차량 유형, 계측값, 내구 거리와 C-Formula의 휘발유 기준이 준비되면 즉시 표시됩니다. 에너지 점수는 기존 내구 최종 기록, 에너지 총점 및 상대점수 기준팀이 준비되면 계산됩니다.
* 내구 미완주, 평균 랩타임 145% 초과, 보정 소비량 60.06 kg CO₂/100km 초과는 에너지 DSQ로 자동 처리됩니다. 봉인·안전 등 오피셜 판정은 에너지 DSQ 버튼으로 선택합니다.
* 음수 순사용 전력량은 회생 충전량이 사용량을 초과한 경우로 보고 설정된 에너지 총점을 부여합니다. 정확히 0은 자동 계산하지 않고 판정 대기로 표시합니다.

## 7. 코스 관리

RTK GPS 로버를 활용한 주행 코스 콘 배치 관리 서비스입니다. 코스·콘·경로·메모 편집은 `course.operate`, 스냅샷과 코스 삭제는 `course.manage`, 로버·카메라·GPS·미션 운용은 `rover.operate`가 필요합니다. `course.manage`와 `rover.operate`에는 각각 `course.operate`가 포함됩니다.

### 코스

* 패널 상단에서 코스를 생성하고 관리합니다.
* 각 코스의 지도 표시 여부를 변경하거나 활성 코스를 선택할 수 있습니다.

### 콘 관리

* **지도 클릭**: 현재 선택된 방향(L/M/R)의 콘이 클릭 위치에 추가됩니다.
* **드래그**: 활성 코스의 콘을 드래그하여 위치를 이동합니다.

### 로버

* **위치 수신**: 로버의 현재 GPS 좌표를 수신하여 해당 위치에 콘을 추가합니다.
* 로버는 서버에 SSE로 연결되어야 합니다 (`INTERNAL_SECRET` 인증 필요).
* 로버의 마지막 위치는 보라색 마커로 지도에 표시됩니다.

### 주행 순서 마커

주행 방향은 **주행 순서 마커로만** 지정합니다. 별도의 진행방향 전환 버튼은 없습니다.

* 편집 잠금을 해제하고 지도 우측 상단의 **🚩 주행 순서** 도구를 켭니다.
* 빈 노면을 누르면 재사용 가능한 물리 마커가 생깁니다.
* 마커를 누르거나 인스펙터의 `＋`를 누르면 방문 단계가 순서 끝에 추가됩니다. 같은 마커를 여러 번 추가할 수 있습니다. 위·아래 버튼으로 순서를 조정합니다.
* 방문 단계가 2개 이상이면 마커가 시작점과 진행 방향을 결정합니다. 코스명 옆 배지가 어느 방식으로 계산됐는지 보여줍니다.

| 배지 | 의미 |
|---|---|
| `자동 중심선` | 방문 단계가 0~1개. 코스에 저장된 시작 콘·역방향 값을 그대로 씁니다. |
| `자동 중심선 · 마커 기준` | 마커가 한 바퀴를 한 방향으로 훑습니다. 기존 내구·오토크로스 중심선 계산을 그대로 쓰고, 마커는 시작점과 방향만 지정합니다. **기하는 마커를 놓기 전과 동일합니다.** |
| `마커 경로` | 노면을 다시 지나거나 갈라지는 순서(스키드패드). 마커 경로 계산기가 녹색 점선으로 직접 경로를 만듭니다. |

* 내구·오토크로스처럼 한 바퀴 도는 코스는 마커 2개로 충분합니다. 시작하고 싶은 지점에 하나, 진행하려는 방향으로 조금 떨어진 곳에 하나를 놓으면 됩니다. 첫 구간은 **짧은 쪽 호**로 해석하므로, 일부러 먼 쪽으로 돌려면 반대편에 마커를 하나 더 놓아 순서를 명시합니다.
* 스키드패드는 `진입 → 허리 → 좌측 원 방향점들 → 허리`를 두 번, `우측 원 방향점들 → 허리`를 두 번 추가한 뒤 반대편 `진출` 마커로 끝냅니다. 오류가 표시되면 문제가 난 단계와 가까운 허리·분기점에 방향 마커를 하나 더 배치합니다.
* 마커 이전에 만들어진 코스는 서비스가 처음 뜰 때 저장된 시작 콘·역방향을 재현하는 마커 2개를 자동으로 심습니다. 지도에 나타나는 `시작`·`방향` 마커가 그것이며, 위치를 옮기면 그대로 주행 방향이 바뀝니다.
* ZIP 내보내기는 지도에 보이는 경로와 항상 같은 방식으로 계산합니다. `마커 경로`에서는 반복 방문 구간을 한 번만 메시로 만들므로 허리 노면이 겹치지 않습니다. 콘 고도는 노면과 콘 메시 양쪽에 반영됩니다. 이 경로는 사람이 공식 순서대로 주행하기 위한 것이며 Assetto Corsa 기본 AI의 2+2 랩 판정·주행 자동화는 제공하지 않습니다.

### 경로 계산 및 실행

* **경로 계산**을 누르면 미션 경로 편집기가 열립니다. 코스 전체를 자동 정렬한 상태에서 시작하며, 원하는 콘만 남기거나 검색·방향 필터로 수백 개 콘을 일괄 추가할 수 있습니다. 완료한 방문을 포함해 한 미션은 최대 1,000회 방문으로 제한됩니다.
* 오른쪽 주행 순서에서 드래그, ↑/↓, 순번 직접 입력, 역순, 현재 로버 위치 기준 자동 정렬을 사용할 수 있습니다. `＋`는 같은 콘을 다시 방문하고 다시 분사하는 명시적 반복 항목을 추가합니다.
* 자주 쓰는 콘 부분집합·순서·종료 동작은 코스별 이름 있는 프리셋으로 저장할 수 있습니다. 삭제된 콘이 포함된 프리셋은 실행되지 않으며 수정 또는 삭제해야 합니다.
* 마지막 콘 이후 동작은 **그 자리에서 정지**(기본) 또는 **최초 미션 시작점으로 복귀** 중에서 고릅니다.
* **경로 실행**은 서버에 미션과 고유 웨이포인트 ID를 먼저 저장한 뒤 로버의 수락 응답을 기다립니다. 일반 `IDLE` 텔레메트리만으로 미션이 완료되지는 않습니다.
* 일시정지·비상정지·pilot 재시작·로버 재부팅 후에는 항상 운영자가 **이어서 실행**을 눌러야 움직입니다. 완료된 콘은 다시 방문하지 않고 동일한 미션 ID의 남은 항목만 재개합니다.
* 분사 명령 이후 결과가 오기 전에 전원이 끊기거나 분사를 취소하면 해당 방문은 **결과 확인 필요**로 표시되고 자동 재분사하지 않습니다. 분사했다고 판단하면 그 방문을 제거하고, 다시 분사하려면 제거한 뒤 같은 콘을 새 방문으로 추가하세요. 마지막 남은 방문도 빈 경로로 저장해 건너뛸 수 있습니다.
* 정지 중에는 **남은 경로 편집**으로 미완료 콘을 추가·제거·재정렬할 수 있습니다. 제거한 항목은 감사 이력에 `skipped`로 남습니다.
* **비상정지**: 로버에 즉시 정지 명령을 전송합니다.
* **수동 제어**: 로버가 실제 정지를 보고한 미션에서만 경로를 버리지 않고 로버를 옮길 수 있습니다. 네트워크가 끊겨 서버에 `interrupted`로 보이더라도 로버가 기존 경로를 계속 주행할 수 있으므로 정지 확인 전 수동 이동과 경로 편집은 서버가 거부합니다.

## 8. 엔트리 관리

엔트리와 차량 유형은 연도별 데이터입니다. 현재 연도는 Entry, Queue, Registration, Inspection, Traffic, Score, Documents에서 동시에 사용하며 별도의 명단 확정 단계는 없습니다. 과거·미래 연도는 조회만 가능합니다. 현재 연도는 한국 시간(`Asia/Seoul`)으로 판정됩니다.

기존 팀을 수정해도 안정적인 내부 ID는 유지됩니다. 번호·학교·팀명·차종을 고치면 연결된 운영 데이터의 표시용 정보가 같은 트랜잭션에서 함께 갱신됩니다. 팀 삭제 기능은 없으며, 더 이상 참가하지 않는 팀은 비활성화합니다. 비활성화해도 이력은 보존되고 진행 중인 대기열·무선 계측 같은 일시 상태만 정리됩니다.

엔트리는 대회 운영 전에 확정하는 것을 원칙으로 하며, 운영 중 변경은 드문 예외 상황으로 취급합니다. 엔트리를 추가·수정·비활성화하면 Queue, Registration, Inspection, Traffic 화면은 SSE 알림 후 최신 정식 엔트리를 다시 조회합니다. 서버도 저장할 때 안정적인 팀 ID로 최신 엔트리를 다시 확인하므로 오래 열린 화면의 예전 학교명·팀명·번호가 새 기록으로 저장되지는 않습니다. 팀 비활성화는 진행 중인 일시 상태를 정리하므로 확인창을 거쳐 실행됩니다.

JSON 업로드는 현재 연도에 팀이 하나도 없을 때 한 번만 사용할 수 있는 초기 입력 기능입니다. 기존 명단을 교체하거나 합치는 기능이 아니므로, 이후 변경은 개별 팀 편집을 사용합니다.

## 9. 대회 일정

대회 일정을 관리합니다. 별도의 관리 메뉴는 없으며, 홈의 **대회 일정** 화면 하나에서 조회와 편집을 모두 처리합니다.

누구나 월간 뷰와 리스트 뷰에서 일정을 조회할 수 있으며, 일정은 `public`, `student`, `official` 중 지정된 공개 대상에 맞게 노출됩니다(기본값 `official`).
`calendar.manage` 권한이 있으면 같은 화면에 추가/수정/삭제 버튼이 나타납니다.

- `calendar.manage`가 있으면 날짜를 클릭해 일정을 추가할 수 있습니다.
- `calendar.manage`가 있으면 일정을 클릭해 수정/삭제할 수 있습니다.
- 종일 이벤트와 시간 지정 이벤트를 모두 지원합니다.
- 모바일에서는 리스트 뷰가 기본으로 표시됩니다.

## 10. 계정 관리

로그인 계정과 권한을 설정합니다.

구글 로그인이 가능한 이메일 주소를 사용하여 등록합니다.

사람 계정 역할은 `student`, `official`, `admin` 중 하나입니다. 오피셜을 선택하면 서비스별 접근 수준을 한 목록에서 설정할 수 있습니다. 관리 권한은 같은 서비스의 운영 권한을 자동으로 포함합니다. 역할을 바꾸면 기존 오피셜 권한은 모두 제거되며, 동시에 열린 관리자 화면의 오래된 변경은 revision 충돌로 거부됩니다.

기존 `staff`, `chief`, `master` 계정은 업데이트 시 서비스 권한이 없는 `official`로 전환됩니다. 필요한 서비스 권한은 관리자가 명시적으로 다시 지정해야 합니다.

공용 접수 태블릿은 `계정 및 권한`의 `태블릿 장비 관리`에서 이름과 용도 하나를 선택해 생성합니다. 태블릿에서 `/auth/device`를 열어 10분 동안 유효한 8자리 코드를 한 번 입력하면 이후 재방문에도 인증이 유지됩니다. 서버에는 장비 토큰의 해시만 저장됩니다. 코드 재발급은 기존 토큰을 즉시 무효화하고, 폐기한 장비는 다시 페어링하기 전까지 사용할 수 없습니다.

운영오피셜 연락처를 등록하면 official과 admin 계정의 사이드바 상단에 연락처가 표시됩니다. 연락처 표의 설명 열을 클릭해 짧은 설명을 입력하면 사이드바에서 이름 뒤에 함께 표시됩니다. 순서 열의 드래그 핸들을 마우스나 터치로 끌어 사이드바 표시 순서를 조정할 수 있으며, 새 연락처는 목록 마지막에 추가됩니다.

## 11. 권한

사람 계정 역할은 세 종류뿐이며, 오피셜의 운영 범위는 서비스 권한으로 구성합니다. `*.manage`는 같은 서비스의 `*.operate`를 포함하지만, 서로 다른 서비스 권한은 자동으로 따라오지 않습니다. 예를 들어 `queue.manage`는 `queue.operate`를 포함하지만 `inspection.operate`는 포함하지 않습니다.

### 공개 (public)

로그인 없이 접근 가능한 기능입니다.

| 서비스 | 기능 |
|---|---|
| 랜딩 페이지 | 전체 |
| 검차 대기열 | 대기 현황 조회 |
| 등록 대기열 | 접수 현황 및 전화번호 인증을 통한 내 순번 조회 |
| 엔트리 | 엔트리 목록 조회 |
| 에너지미터 | 전체 |
| 규정집 | 전체 |
| 대회 일정 | public 공개 범위 일정 조회 |

### 학생 (student)

각 팀별로 한 명씩 등록되는 계정입니다.

| 서비스 | 기능 |
|---|---|
| 서류 제출 | 파일 업로드 및 제출 |
| 대회 일정 | student 공개 범위 이하 일정 조회, iCal 구독 |
| 등록 대기열 | 공개 사용자와 동일한 대기 현황 및 내 순번 조회 |

### 오피셜 (official)

대회 운영자 계정입니다. 계정마다 필요한 서비스 권한만 부여합니다. 홈과 사이드바의 Operations에는 실제로 접근 가능한 메뉴만 표시되고, 관리자 전용 도구는 별도의 Admin 그룹에 관리자에게만 표시됩니다.

계정 및 권한 화면의 사용자 목록에는 계정마다 부여된 권한이 배지로 표시됩니다. 여러 계정을 체크한 뒤 **선택 권한 설정**을 누르면 선택한 Official 전원의 권한을 한 번에 같은 목록으로 바꿀 수 있습니다. 선택한 계정의 권한이 서로 다르면 공통 권한만 미리 체크된 상태로 열리고, 저장하면 모든 대상의 권한이 대화상자의 설정으로 교체됩니다. Official이 아닌 계정은 대상에서 제외됩니다.

등록 대기, 검차 대기, 인스펙션, 서류, 계측은 `없음/운영/관리` 중 하나를 선택합니다. 관리는 해당 운영 권한을 자동으로 포함합니다.

| 영역 | 운영 | 관리 |
|---|---|---|
| 등록 대기 | 대기 조회·완료·취소 | 현장 접수·설정 |
| 검차 대기 | 대기열·부스·페널티·통계 운영 | 수동 접수·우선순위·초기화·설정 |
| 인스펙션 | 검차표 입력·판정 | 템플릿 관리 |
| 서류 | 제출 현황·파일 검토 | 세션·학생 매핑·파일 변경/삭제 |
| 계측 | 경기와 일반 기록 운영 | 설정·센서 매핑·전체 삭제 |

코스와 성적은 단일 체크박스입니다. 코스를 허용하면 코스·콘·경로·메모 편집과 스냅샷·삭제를 모두 사용할 수 있고, 성적을 허용하면 집계·입력과 페널티·배점·공개 관리를 모두 사용할 수 있습니다. 그 밖에 파일 클라우드, 일정 관리, Rover 운영 권한을 독립적으로 부여할 수 있습니다. 엔트리 관리, 이메일/SMS, 시스템 로그는 오피셜에게 부여할 수 없는 관리자 전용 도구입니다.

### 관리자 (admin)

모든 서비스 권한을 자동으로 가지며, 홈과 사이드바의 Admin 그룹에 표시되는 관리자 전용 도구를 사용합니다.

| 서비스 | 기능 |
|---|---|
| 서비스 전체 | 모든 code-defined 서비스 권한 |
| 엔트리 관리 | 팀과 차량 유형 관리 |
| 이메일/SMS | 이메일·SMS 발송, 테스트, 통계, 전송 기록과 자격 증명 설정 |
| 시스템 로그 | 전체 서비스 감사 로그 조회 |
| 계정 및 권한 | 계정 생성·역할·권한 변경·삭제, 일괄 권한 설정, 계정 신청·운영 연락처·접수 전용 태블릿 관리 |

### 접수 전용 태블릿

사람 역할이 아닌 장비 principal입니다. 장비 하나는 아래 범위 중 정확히 하나만 가집니다.

| 범위 | 허용 기능 |
|---|---|
| `kiosk.queue.register` | 검차 대기 접수 화면과 해당 등록 요청 |
| `kiosk.registration.register` | 등록 대기 접수 화면과 해당 등록 요청 |

대기 운영, 설정 변경, 인스펙션, 다른 접수 종류나 관리자 화면에는 접근할 수 없습니다. 한 브라우저에 사람 세션과 장비 세션이 동시에 있으면 요청을 모호한 principal로 거부합니다.
